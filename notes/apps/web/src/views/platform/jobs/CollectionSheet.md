# `apps/web/src/views/platform/jobs/CollectionSheet` 笔记

> 摘自 `apps/web/src/views/platform/jobs/CollectionSheet.tsx` 的模块说明与注释。

## 一句话

采集条件表单：搜索条件 + 采集参数 + 期望流来源一次改完，保存压平。

## 细节

- 两块配置（搜索条件 + 采集参数 + 期望流来源）一次改完，保存走 `toSaveBody` 压平。
- 每次打开重置草稿，免得上次没保存的改动漏进下一次。
- 期望列表走缓存（登录时拉好、手动同步刷新），不在每次打开都打真接口；「同步」从旧期望页搬到这里的「采集来源」档。

### caps 降级（docs 3.3 / 成功标准 #3）

- `caps.catalog.unsupported` 点名的维度 → 置灰并标注「该平台不支持」，不硬塞；
- `caps.source.expect_flow` 为假 → 期望流来源整档不出现（不是点了报错）。

### 表单细节

- 城市级联走全量城市树（省 → 市），叶子即市级 code（缺陷「城市仅有热门城市」）；
- 行业级联：组导航、选项勾选，确定才提交（缺陷「行业无法级联选择」）；
- 采集参数左文案右数字，每项一行（提议「采集参数分别一行」）；
- 保存 / 重置分开记在飞状态：按钮各自转文案，又互斥禁用（同时只发一个请求）。
