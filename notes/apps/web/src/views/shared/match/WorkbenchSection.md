# `views.shared.match.WorkbenchSection` 布局与搜索范围笔记

> 摘自 `apps/web/src/views/shared/match/WorkbenchSection.tsx` 的模块 docstring / 行内注释。

## 一句话

匹配工作台：发起匹配（搜索范围 + 可选勾选）+ 任务进度 + 匹配结果。

## 细节

布局（缺陷清单「匹配工作台布局」）：左栏搜索/配置（固定宽），右栏任务进度 + 结果（flex 1），
窄屏（xs）才落回上下堆叠。

搜索范围（缺陷清单「搜索范围」）：只留「爬取批次下拉 + 搜索框」同一行——
不选批次 = 搜全部职位；勾具体岗位 = 只匹配这几个，不勾 = 范围内全部。
不再有「全部岗位 / 抓取批次」互斥分段。

结果/任务状态是页面级的（切到历史、招呼语再回来还在），这层只管发起与展示；
保存招呼语 / 重打草稿 / 单条重跑的动作也在这层（跟结果卡走）。

## 实现备注

- 搜索词防抖 300ms：每敲一个字都打后端会把职位表翻烂。
- 单条操作要读「当下」的草稿/结果快照：走 ref 读最新值，回调就不绑 state 依赖、引用全程稳定，
  MatchCard 的 memo 才拦得住（缺陷「展开收起卡顿」：状态一变全部卡片跟着重渲染）。
- `matchApi.analyze` 的 repos 回包类型被收窄成 `{task_id}`，实际是整份 `MatchTask.snapshot()`
  （`boss_web/api/match.py start_match`）。
- 生成是异步任务：WS 统一快照优先（推得快），轮询业务快照兜底。
